作为播放事件埋点模块，显然这个“事件”的 pojo 是必要的，也很自然地会想到需要去设计一个播放事件表，不然埋什么点呢。这些内容的设计中，需要留个心眼的，我觉得就是类型为 LocalDateTime 的那几个字段了，它们的序列化问题着实有些特殊🥲。哦对了，后来我还给实体/表加了幂等写入键，防止重复写相同数据。

对于三层架构，Mapper 自然不用说，都用 MyBatis-Plus 了。服务层的话…目前似乎也就需要一个 save 事件的方法。单纯对这个模块来说，它不需要暴露什么请求接口，因为“埋点”嘛，只需要在曲目播放事件发生时（TrackController中）触发就行。

无法序列化对象？查了资料发现，是“在无参构造时会创建一个纯净的 Jackson ObjectMapper，这个 ObjectMapper 不包含 JavaTimeModule，因此遇到 LocalDateTime 类型时无法序列化，抛出异常”。

嘶，那怎么办？最开始想到的是既然它默认是新建一个纯净的 Jackson ObjectMapper，那我通过个配置类重新注入一个带 JavaTimeModule 的 ObjectMapper？不用它默认的。把这个想法告诉AI✌，我滴妈，太鸡儿麻烦了，pass。

然后么…那换成 org.apache.kafka.common.serialization.StringSerializer，然后两边都自己手动(反)序列化JSON字符串？咕，那也太烦了，杀了我吧。结果还是试着做了，结果呢…

What’s up，Bean 都搞没了喔。我在生产者和消费者中都引入了 com.fasterxml.jackson.databind.ObjectMapper 来手写JSON字符串解析逻辑，但是这不对。查了下发现，新版本 Springboot 中，自动配置的 ObjectMapper 已经不在 fasterxml 下了。

那到底是怎么回事呢？我拿着完整的问题与现象去求助蓝色大肥鱼：

然后她给出了正确的解释，我真是爱死她了muamuamua（づ￣3￣）づ╭❤～

以下是大肥鱼对这个问题的回答：

问题根源：Spring Boot 4 中的“双 Jackson”现象

Spring Boot 4 默认使用 Jackson 3（包路径 tools.jackson），其 JsonMapper 已经内置了对 LocalDateTime 的支持，无需额外模块。然而，Spring Kafka 4.1 同时提供了两套 JSON 序列化器：

序列化器类 Jackson 版本 对应 Mapper 类型
JsonSerializer / JsonDeserializer Jackson 2 com.fasterxml.jackson.databind.ObjectMapper
JacksonJsonSerializer / JacksonJsonDeserializer Jackson 3 tools.jackson.databind.json.JsonMapper

你在 YAML 中配置的若是 **JsonSerializer**，实际使用的是 Jackson 2 的实现，它默认不会自动注册 JavaTimeModule，因此序列化 LocalDateTime 时会抛出 InvalidDefinitionException。

最后全部换成如当前所示的 Jackson3 的序列器就好了。我说怎么这么诡异，给我 Bean 都莫名其妙的整没了，合着是版本更新，用的老兵(Bean)退环境了^^;)

话说回来这个问题好像也不是我一个人遇到，此事在 Spring Boot 4.1 and Apache Kafka: Producer, Consumer and Serialisation from Scratch 中亦有记载。
